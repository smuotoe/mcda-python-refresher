# The race: pip vs uv

<div class="text-xs opacity-70 -mt-3 mb-1">Windows PowerShell shown. It has no <code>&&</code>, so run one line at a time. Try it if the Wi-Fi allows.</div>

<div class="text-sm font-bold text-orange-400">Round 1: venv + pip</div>

```powershell
python -m venv .venv
.venv\Scripts\activate
Measure-Command { pip install pandas numpy matplotlib scikit-learn requests }
```

<div class="text-sm font-bold text-emerald-400 mt-2">Round 2: uv, cold (no cache)</div>

```powershell
deactivate
uv init race-uv
cd race-uv
Measure-Command { uv add --no-cache pandas numpy matplotlib scikit-learn requests }
```

<div class="text-sm font-bold text-emerald-400 mt-2">Round 3: uv, warm cache (a fresh project, without <code>--no-cache</code>)</div>

```powershell
cd ..
uv init race-uv2
cd race-uv2
Measure-Command { uv add pandas numpy matplotlib scikit-learn requests }
```

<div class="text-xs opacity-70 mt-1">macOS/Linux: <code>source .venv/bin/activate</code>, and <code>time pip install ...</code> instead of <code>Measure-Command { ... }</code>. New to uv? Your cache starts empty, so repeat round 3 in one more fresh project to see the warm time.</div>

<!--
[0:17-0:22] Demo on the projector; students can follow along.

- Round 1: plain venv + pip. Start it, keep talking while it runs.
- PowerShell often blocks .venv\Scripts\activate (execution policy: "running scripts is disabled"). Either run `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`, or skip activation and call `.venv\Scripts\pip install ...` directly. # Projects: uv init and uv run

<div class="grid grid-cols-2 gap-5 mt-1">

<div>

```bash
uv init --no-package my-app
cd my-app
uv run main.py
```

```text
my-app/
├── .git/             a git repo, ready to commit
├── .gitignore
├── .python-version   which Python this project uses
├── README.md
├── main.py
├── pyproject.toml    name, version, dependencies
├── .venv/            created by the first uv run
└── uv.lock           created by the first uv run
```

</div>

<div>

```toml
# pyproject.toml
[project]
name = "my-app"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.13"
dependencies = []
```

<div class="mt-2 px-3 py-2 rounded border-l-4 border-emerald-500 bg-emerald-500/10 text-sm">
<b>No activation, ever.</b> <code>uv run</code> creates <code>.venv</code> and <code>uv.lock</code> when needed, syncs them, then runs your code.
</div>

<div class="mt-2 text-xs opacity-70">
Plain <code>uv init my-app</code> (current uv) makes a packaged app instead: code in <code>src/my_app/</code>, run with <code>uv run my-app</code>. <code>--no-package</code> keeps the simple <code>main.py</code> layout.
</div>

</div>

</div>

<div class="sources">
Sources: <a href="https://docs.astral.sh/uv/concepts/projects/init/">docs.astral.sh/uv/concepts/projects/init</a>
</div>

<!--

- `uv run main.py`: first run creates .venv and uv.lock, then prints "Hello from my-app!". No activate step.

# Scripts that bring their own dependencies

<div class="grid grid-cols-2 gap-4 mt-1">

<div>

<div class="text-sm opacity-80 mb-1">PEP 723: dependencies live inside the file</div>

```python
# /// script
# requires-python = ">=3.13"
# dependencies = [
#     "httpx>=0.28.1",
#     "rich>=15.0.0",
# ]
# ///
import httpx
from rich import print

url = "https://pypi.org/pypi/uv/json"
version = httpx.get(url).json()["info"]["version"]
print(f"[bold green]Latest uv:[/] {version}")
```

```bash
uv init --script check.py
```

# Borrow a package or a tool for one command

<div class="text-sm font-bold text-emerald-400 mb-1">A package for one run: <code>uv run --with</code></div>

```bash
uv run --with rich python -c "import rich; rich.print('[bold green]hello')"
uv run --with jupyter jupyter lab   # Jupyter on this project, not added as a dependency
uv add --dev ipykernel              # notebooks in VS Code: pick .venv as the kernel
```

<div class="text-sm font-bold text-emerald-400 mt-3 mb-1">A tool: <code>uvx</code> and <code>uv tool</code></div>

```bash
uvx pycowsay "hello"     # run a tool once, in a throwaway environment
uvx ruff check .         # lint this folder without installing Ruff
uv tool install ruff     # install for good: ruff is now on your PATH
uv tool list             # what's installed
uv tool upgrade --all    # upgrade every tool
```

<div class="mt-3 text-sm opacity-80">
<code>uvx</code> is short for <code>uv tool run</code>, like <code>npx</code> for Node. Each tool gets its own environment, so tools never break your projects.
</div>

<div class="sources">
Sources: <a href="https://docs.astral.sh/uv/guides/tools/">docs.astral.sh/uv/guides/tools</a> · <a href="https://docs.astral.sh/uv/guides/integration/jupyter/">docs.astral.sh/uv/guides/integration/jupyter</a>
</div>

<!--
[0:30-0:32] Two ideas: borrow a package (--with) and borrow a tool (uvx).

- `--with` is perfect for "I just need pandas for this one-liner" or Jupyter without polluting pyproject.toml.
- VS Code notebooks need ipykernel in the environment; add it as a dev dependency, then select .venv as the kernel.
- `uvx pycowsay "hello"`: fun demo, and it shows the throwaway environment.
- `uvx ruff check .`: Ruff is a fast linter (also by Astral). Run it on any folder.
- `uv tool install`: for tools you use daily. They live in isolated environments, so upgrading one never breaks another.
-->
